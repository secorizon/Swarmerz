# Installation and platform support

Swarmerz requires Python 3.12 or newer. It is supported directly on Linux and macOS; Windows users
should run it inside WSL2. Native Windows is not supported because the runtime relies on POSIX
signals, permissions, hardlinks, and terminal behavior.

Swarmerz is not published automatically as part of the release preparation process. Until a release
is explicitly approved and published, install from a reviewed checkout or a locally built wheel.

## Install from a checkout

```bash
cd /path/to/Swarmerz
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/swarmerz --version
.venv/bin/swarmerz doctor
```

For editable development work, install the test extra:

```bash
.venv/bin/python -m pip install -e '.[test]'
```

The checkout launcher, `./bin/swarmerz`, remains available for source-tree use. Installed
deployments should use the `swarmerz` console command generated by the package.

## Install a locally built wheel

Build artifacts in an isolated release environment:

```bash
python3 -m venv .release-venv
.release-venv/bin/python -m pip install '.[release]'
.release-venv/bin/python -m build --wheel
```

Install the resulting wheel into the target environment:

```bash
python3 -m venv /path/to/swarmerz-venv
/path/to/swarmerz-venv/bin/python -m pip install dist/swarmerz-0.1.0-py3-none-any.whl
/path/to/swarmerz-venv/bin/swarmerz doctor
```

The exact wheel version changes with the product version. Do not assume that a locally built
artifact has been published.

## Runtime dependencies

The package manager installs the two Python runtime dependencies:

- `prompt-toolkit` for the operations deck.
- `jsonschema` for structured artifact validation.

Model harnesses are external tools selected by the deployment profile. Install only those required
by the configuration. A pinned harness may be resolved through `npx` when Node.js/npm is installed;
an already installed `codex` or `opencode` executable does not require `npx`.

Release artifacts do not contain a deployment profile. Obtain a template from the source repository,
review every route and path, and pass the resulting file with `--config`.

## Platform helpers

Clipboard integration is optional and never blocks mission execution.

| Platform | Helper | Behavior when missing |
|---|---|---|
| Linux/Wayland | `wl-copy` from the `wl-clipboard` package | Startup and doctor warning; missions still run. |
| Linux/X11 | `xclip` or `xsel` | Startup and doctor warning; missions still run. |
| macOS | Built-in `pbcopy` | Startup and doctor warning; missions still run. |
| SSH or compatible terminal | OSC 52 support in the attached terminal | Copy request may be sent without an acknowledgement. |

Ubuntu and Debian-family Wayland systems can install the helper with:

```bash
sudo apt install wl-clipboard
```

Swarmerz detects `wl-copy`; it does not bundle or install it. VTE terminals that do not implement
OSC 52 report copying as unavailable when no native helper can confirm the copy.

## Doctor checks

Run package and platform checks without loading an operational profile:

```bash
swarmerz doctor
swarmerz doctor --json
```

Check a deployment profile and all harnesses it requires:

```bash
swarmerz doctor --config /absolute/path/to/swarmerz.toml
```

Doctor verifies Python, supported platform, clipboard integration, Linux resource-containment
helpers, Python dependencies, packaged schemas, and—when a profile is supplied—the configured
harness executables. Mission startup additionally exercises the user-systemd controls before any
harness launches. Warnings such as a missing optional clipboard helper or unavailable automatic
resource containment return success. Missing required dependencies, schemas, platform support,
configured harnesses, or containment configured as `required` return failure.

## Platform notes

### Linux

Run inside an interactive terminal. Keep the durable `output_root` and disposable cache on a local
filesystem with normal POSIX permissions. When user-systemd scopes are available, Swarmerz uses
them for harness memory, swap, and task ceilings without placing the controller in the same scope.
A remote model endpoint is supported as long as its configured harness can reach it.

### macOS

Install Python and each configured harness for the same CPU architecture. `pbcopy` provides native
clipboard integration. Package installation, doctor, the console command, and the test suite are
covered by the macOS CI job. Linux cgroup ceilings are unavailable; automatic mode keeps normal
process-group timeout cleanup and does not block the mission.

### Windows through WSL2

Keep the checkout, frozen context, artifacts, and cache on the WSL Linux filesystem rather than a
mounted Windows drive. Install the Linux versions of Python and the selected harnesses inside WSL.
